# Navigation analysis

The navigation viewer opens as a collapsible tree. Each destination is expanded once on its shortest route from the entry page; other links remain visible as shared destinations or cycle references. Search and confidence, transition-kind, and HTTP-method filters apply to both the tree and graph. Arrow keys navigate and expand the tree; Enter selects a transition. The graph remains available through the view switch.

In graph mode, transitions use separate connection points and directed paths, including parallel requests and returns to the same page. Selecting a page keeps its immediate connections highlighted: incoming transitions are blue, outgoing transitions are amber, and self-returns are purple. Uncertain transitions use dashed lines. The expandable **How to read the graph** explains line styles, direction, page colors, and selection colors. Overview labels are hidden initially; focused transitions and loop returns retain their labels. Cyclic return edges and self-returns are labeled **Loop** (ループ); ordinary shared destinations are not loops. **Fit connections** zooms to the focused page or transition and its neighbors; **Clear selection** restores the overview. The inspector lists incoming and outgoing transitions and lets you follow either endpoint without searching the graph again.

Workspace and folder graphs arrange independent connected groups separately and collect pages without transitions into a compact grid. Short routes flow horizontally; longer chains flow vertically. Include-only relationships and disconnected include helpers are omitted. Fragments remain visible when they are actual transition endpoints. Graph lines and arrows stay legible when zooming, and fit operations include return paths outside page cards.

VBScript helper arguments and assigned target values are resolved in each calling page's execution context. Client JavaScript helpers can also be shared across classic script blocks and expanded includes in the same execution program. Resolved helper transitions originate at the calling page and retain the outer invocation's source position; relative targets use that page's directory. Finite ASP values are carried across classic scripts and includes, preserving the original file/range evidence for both the caller and its dependencies. Inline modules run after classic scripts in separate lexical scopes; module-local variables and functions do not leak between modules. Imported bindings shadow globals; this pass does not load imported module files and keeps those bindings unresolved. Async modules retain conservative per-region analysis. The combined client script analysis is bounded to 8 MiB and shares cancellation and finite-evaluation limits.

The navigation graph, flowchart, and workspace-files webviews use pinned Solid 2 release-candidate packages. Shared source highlighting, IME-aware inputs, and virtual lists use Solid components. All three webview roots remove VS Code's default body padding while keeping spacing inside controls. The flowchart reserves at least 360 pixels for its canvas when side panes are visible. Narrower windows switch to Graph / Information / Source tabs and restore the requested pane widths when expanded; Ctrl/Cmd+F opens the Information tab and focuses search.

Unresolved destinations are separated by their source occurrence. Selecting one displays the source file, one-based line and column, and the original statement. **Open source** selects the target expression when its exact range is available, otherwise the recorded statement or attribute. Include evidence continues to point to the declaring file. Source coordinates use LSP UTF-16 positions.

VBScript navigation analysis evaluates finite literal arguments to `Replace`, `Left`, `Right`, `Mid`, `LTrim`, `RTrim`, `Chr`, and `ChrW`, including nested expressions, user functions, and finite branch alternatives. Arguments execute once in the evaluator so function effects are retained. String operations share the request work budget and the existing finite-value cap. UTF-16 slicing that splits a surrogate pair, runtime-dependent arguments, locale-dependent `Chr` values outside ASCII, and non-binary `Replace` comparisons remain unresolved.

HTML forms with missing or empty actions submit to the current document. Submit-control overrides inherit their form's method, target frame, and hidden parameters, including controls associated through `form="id"`. Explicit overrides take precedence. Dialog submissions and non-submitting or disabled controls do not create navigation edges. Missing closing form tags retain an explicit action even when a body cannot be recovered.

The tree constructs at most one expanded entry per node plus references for the remaining edges, uses iterative traversal, and virtualizes visible rows. ELK layout runs only while graph mode is active. Shared VBScript source indexes and per-form parameter caches avoid repeatedly scanning the same source while collecting evidence.

Literal type regression coverage exercises exact strings (including Unicode and doubled quotes), numeric spelling/radix equivalence, Boolean identity, mixed unions, and mismatches. JSON-RPC tests check hover, completion resolve, and enabled inlay hints. Completion details use the cursor's lexical scope and assignment prefix; a later dynamic assignment must not erase an earlier literal value or leak a local value into the global scope. Constants keep their existing widened primitive types.
